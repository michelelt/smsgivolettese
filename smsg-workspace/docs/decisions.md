# Decisions (ADR)

Format: context · decision · consequences. Status "accepted" unless marked.

### ADR-001 Identifier language
Context: brief mixes Italian/English names; CLAUDE.md says code in English; brief mandates `app_role` values incl. `volontario`.
Decision: tables/columns/functions in English (glossary in `data-model.md`, aligned with `smsg-context`); enum **values** in Italian exactly as in the brief.
Consequences: SQL/TS read naturally; enum values map 1:1 to UI labels and the brief; no translation layer for statuses.

### ADR-002 API queries run under the caller's Postgres role
Context: postgres.js on the pooler connects as a privileged user, which bypasses RLS, so RLS would not be a second line of defence.
Decision: every request query runs in a transaction that sets `request.jwt.claims`, `role` (`authenticated`/`anon`) and `app.request_id` with `set_config(..., true)`; service mode only for cron, invites, bootstrap, rate limit. `prepare: false` (transaction pooler).
Consequences: RLS and `auth.uid()` work in policies, triggers and audit; one extra round-trip per request; every DB call must go through `db.asUser/asAnon/asService`.

### ADR-003 Supabase Data API not used
Context: the web never queries tables; the publishable key is public, so PostgREST would expose a second write path that skips Turnstile/Zod.
Decision: remove `public` from exposed schemas (Data API off) in both projects; helpers in non-exposed schema `app`.
Consequences: smaller attack surface; anon policies still matter because the API runs public reads as `anon`.

### ADR-004 Volunteer overlap via `volunteer_commitments` + exclusion constraint
Context: brief allows a view/materialized table of commitments or a trigger.
Decision: real table maintained by security-definer triggers on `shift_assignments`, `shifts`, `transports`, with `exclude using gist (volunteer_id with =, period with &&)`.
Consequences: race-free (a trigger-only check races under READ COMMITTED; a matview cannot reject writes); one error code (23P01) for all conflicts; small denormalisation kept in sync in the same transaction.

### ADR-005 One role per user; min-role permission map
Decision: `user_roles.user_id` is the PK; `app_role` enum ordered `volontario < staff < super_admin`; `permissions.ts` maps action → minimum role; SQL `app.has_role(min)` mirrors it.
Consequences: hierarchy is trivial to check in TS and SQL; an action that is not monotonic in the hierarchy would need a different model (none today).

### ADR-006 Public writes through definer functions; client matching
Context: no account for public users; anon must not get table insert rights.
Decision: `submit_public_booking` / `submit_post_proposal` (granted to anon) called by the API after Turnstile + rate limit. Booking attaches to an existing client by normalised phone + last name, never updating that client; otherwise creates one.
Consequences: no anonymous overwrites; possible duplicates are fixed by staff (merge not in scope).

### ADR-007 Settings split
Decision: `site_settings` (public, anon-readable) and `org_settings` (issuer data, stamp duty, fee amount, card counter, video limit; super_admin only), both single-row.
Consequences: anon select on a whole row is safe; fiscal/config data stays private.

### ADR-008 Invoices: immutable snapshot, PDF on demand
Decision: invoices snapshot issuer/customer/amounts; triggers allow only pay/void transitions; no deletes; `bookings.invoice_id` marks the current invoice (cleared on void); PDFs (invoice, receipt, travel sheet) generated by `pdfkit` per request, not stored. Credit notes out of scope (prototype copy).
Consequences: deterministic re-rendering; no storage of documents; voided numbers stay in sequence.

### ADR-009 Money in integer cents
Context: project convention (`smsg-context`).
Decision: all amounts `int` cents, including stamp threshold (7747) and amount (200).
Consequences: no float/rounding issues; conversion only at UI/PDF/CSV.

### ADR-010 Storage
Decision: public bucket `media` (uuid paths, 50 MB limit = Supabase free cap) and private bucket `proposals`; `media` row created only after the API verifies the uploaded object; orphan cleanup in daily cron.
Consequences: drafts' images are reachable only by unguessable URL; configurable video limit cannot exceed 50 MB on the free plan.

### ADR-011 Revalidation webhook path
Context: `/api/*` on the web domain is rewritten to the API.
Decision: web route `/hooks/revalidate`, shared secret header, tags `posts`, `post:<slug>`, `services`, `site-settings`; 1 h time-based fallback.
Consequences: no route collision; a missed webhook self-heals within an hour.

### ADR-012 Rate limiting in Postgres
Decision: `rate_limit_hits` table + `app.consume_rate_limit()`; IP from Vercel headers.
Consequences: no extra service; to verify the client IP survives the web rewrite (phase 3), fallback Vercel Firewall rule.

### ADR-013 Time zone
Decision: instants `timestamptz`; availability, slots, invoice year and "tomorrow" computed in `Europe/Rome`; cron schedules in UTC.
Consequences: DST handled by Postgres; reminder time drifts by 1 h between summer/winter (acceptable).

### ADR-014 Volunteer data minimisation and writes
Decision: volunteers read transports only via view `volunteer_transports_v` (+ strict Zod response); their writes on shifts/transports/profile go through definer functions; availability uses plain own-row RLS.
Consequences: column-level restriction without per-role grants (all users share Postgres role `authenticated`).

### ADR-015 Transport timing
Decision: `departure_at`, addresses nullable while `richiesto` (public bookings lack them); required from `assegnato`. Busy period = departure → return, else appointment + 1 h, else departure + 2 h.
Consequences: public bookings can create transports; overlap check is approximate when no return time is given.

### ADR-016 Assignment candidates and absences
Context: brief says staff see "only available volunteers" but also labels "già impegnato" and "assente".
Decision: dialog lists all active volunteers, available first (sorted by shifts this month); "già impegnato"/"assente" are shown disabled. API rejects absent volunteers (409 `VOLUNTEER_ABSENT`); overlap is rejected by the DB.
Consequences: staff understand why someone is not selectable; volunteers with no declared availability can still be assigned (shown last, label "non indicata").

### ADR-017 Migrations and deploy order
Decision: API `main`: tests → `supabase db push` (prod) → `vercel deploy --prebuilt --prod`, with Vercel Git auto-deploy for `main` disabled in the API project. PRs with migrations push to staging; staging can be reset.
Consequences: DB always migrated before code; staging may hold migrations of unmerged PRs (reset when needed).

### ADR-018 OpenAPI contract check
Decision: committed `openapi.json`, CI regenerates (must match) and runs `oasdiff breaking` vs `main`; web commits generated `lib/api/schema.d.ts`.
Consequences: breaking changes need a major bump; backward-compatible changes make repo deploy order irrelevant.

### ADR-019 Audit via triggers
Decision: generic `app.audit()` trigger on members, fees, invoices, lines, counters, roles, profiles, volunteers, shifts, assignments, transports, org_settings; actor from JWT claims; GDPR anonymisation redacts affected rows.
Consequences: SQL-function writes are audited too; audit table grows (no retention purge yet).

### ADR-020 Auth details
Decision: JWT verified with `jose` + Supabase JWKS; new key names (`sb_publishable_…`, `sb_secret_…`; legacy anon/service_role work identically); sign-ups disabled; Resend as Auth SMTP; JWT lifetime 15 min; profiles created by the API (no profile trigger on `auth.users`; see ADR-034 for the password_set trigger).
Consequences: deactivation/role change takes effect within 15 min.

### ADR-021 Next.js 16 `proxy.ts`
Context: brief names `middleware.ts`; Next 16 renamed it `proxy.ts`.
Decision: use `proxy.ts` (same role).
Consequences: none functional; update brief references mentally.

### ADR-022 Block editor rendering
Decision: BlockNote in the editor; content stored as BlockNote JSON; custom blocks for gallery, video embed, button, divider where BlockNote lacks them; Zod whitelist on write; small own server renderer (switch per block type → React + `next/image`), not BlockNote's HTML export.
Consequences: full control over accessibility/images; renderer must be extended when a block type is added.

### ADR-023 Prototype features dropped
Context: prototype shows "Le mie prenotazioni", self-cancel and "Le sue proposte", which require an identity; brief says no account for the public.
Decision: not implemented; success screens tell people they will be called back; cancellations by phone.
Consequences: simpler public flow; no public personal data exposure.

### ADR-024 Reminders idempotency
Decision: `reminder_sent_at` on `shift_assignments` and `transports`, set after a successful send; single daily cron (`0 16 * * *` UTC).
Consequences: retries never double-send; works on Vercel Hobby cron limits.

### ADR-025 Counters adjustable upward only
Context: prototype lets staff edit the "last card number"; super_admin owns "numerazioni".
Decision: `set_member_counter` / `set_invoice_counter` (super_admin) only accept values ≥ the highest assigned number.
Consequences: migration from the old register is possible; numbers can never be reissued.

### ADR-026 GDPR retention
Decision: anonymisation keeps invoices (fiscal 10-year retention) and card numbers; personal fields nulled elsewhere.
Consequences: needs confirmation by the association's privacy officer (open question).

### ADR-027 Local secrets file and super admin password
Decision: workspace `secrets.env` (git-ignored, `chmod 600`, template `secrets.env.example`) holds `SUPERADMIN_EMAIL`, `SUPERADMIN_PASSWORD`, `SUPABASE_DB_PASSWORD_{STAGING,PROD}`; Makefile sources it. The super admin password from the file is set only when the account is created; afterwards only the super admin can change it (self-service with reauthentication). Claude Code is denied reading the file.
Consequences: the file password goes stale after the first change (expected); a forgotten password is reset from the Supabase dashboard; CI keeps using GitHub secrets.

### ADR-028 Submodules created in place with relative URLs
Context: no remotes may be added or pushed; a fresh clone must work once the owner pushes.
Decision: `git init -b main` inside `api/` and `web/`, commit, then `git submodule add ../smsg-api api` / `../smsg-web web` (git adopts the existing repo; no clone, no remote). `.gitmodules` URLs are relative, so they resolve against the workspace's GitHub URL once pushed (all three repos under the same owner, named `smsg-api`, `smsg-web`).
Consequences: zero remote config now; the owner must push api/web before the workspace (pinned SHAs must exist); a local fresh-clone test needs `git -c submodule.api.url=<abs>/api ...` overrides.

### ADR-029 Default branch `main` everywhere
Decision: new repos `git init -b main`; workspace renamed locally `git branch -m master main` (safe: no remote). API `staging` branch created in the phase that needs it.
Consequences: matches CI triggers (`main` = production) and ADR-017.

### ADR-030 `make dev` process runner
Decision: `pnpm dlx concurrently@<exact 9.x> -k -n api,web -c blue,magenta "pnpm -C api dev" "pnpm -C web dev"`; no workspace package.json.
Consequences: prefixed coloured output and Ctrl+C/kill-others for free; first run downloads the tool (cached afterwards).

### ADR-031 Toolchain and local API entrypoint
Decision: Node 24 (`.nvmrc`, `engines`), `packageManager: pnpm@12.9.1` in each repo, caret ranges + committed lockfile, CI `--frozen-lockfile`. Latest stable majors at scaffold time: Next 16, React 19, Tailwind 4 (`@tailwindcss/postcss`, tokens via `@theme`), Hono 4 + `@hono/zod-openapi` + Zod 4, Vitest, TypeScript strict, ESLint 9 flat config (`eslint` CLI; `next lint` is gone in 16) + Prettier. API: `api/index.ts` (Vercel) and `src/server.ts` (local only, `@hono/node-server` on :3001, run with `tsx watch`) both import `src/app.ts`. No `vercel dev`.
Consequences: no Vercel login for local dev; confirm in phase 8 that Vercel's build image supports pnpm 12 (else pin the newest supported major).

### ADR-032 Local env files
Decision: `make setup` copies each repo's `.env.example` → `.env.local` only if missing (hand-edited). `make dev`, after `supabase start` (run in `api/`), regenerates `.env.development.local` in api and web from `supabase status -o env` (Supabase URL, keys, DB URL only; mapped to our names). Next loads it natively with precedence over `.env.local`; API loads both via `node --env-file-if-exists` (generated first, then `.env.local`). Supabase CLI config lives only in `api/supabase/`; workspace root `supabase/` (CLI link cache only) is deleted.
Consequences: local keys are never typed by hand or committed; both env files git-ignored.

### ADR-033 OpenAPI generation from the exported file
Context: `make dev` must regenerate the web client before the API is running.
Decision: `pnpm -C api openapi:export` writes `api/openapi.json` by importing the app (no server); `make gen-api` = export, then `OPENAPI_URL=../api/openapi.json pnpm -C web gen:api`.
Consequences: no start-up race; web CI still uses the committed `schema.d.ts`.

### ADR-034 Staff and super admin cannot sign in with magic link or recovery
Context: phase 2 security review; an emailed link (magic link/OTP, recovery) would let anyone with access to a staff mailbox get a privileged session without the password.
Decision (approved by the owner): the Custom Access Token Hook returns an error (no token) when `app_role ∈ {staff, super_admin}`, the account has a recorded password (`app.password_set`), and `authentication_method` or any `amr` method is not `password`/`token_refresh`. GoTrue reports magic link, recovery, invite and email OTP all as `otp`, and GoTrue sets a random password while verifying an invite, so the hook relies on `app.password_set` (a row written by a trigger on `auth.users` when a confirmed user sets a password, or a user is created with one); without that row a link session is issued without `app_role` and can only set the first password; a link-born session also loses refresh once a password exists, so after setting the first password staff sign in again with email and password; volunteers keep magic link + recovery (elderly-friendly). Own password change in `/gestione` always does `reauthenticate()` + emailed nonce in the UI.
Residual risk (accepted): GoTrue `secure_password_change` enforces the nonce server-side only for sessions older than 24 h, so a stolen fresh session could change the password calling GoTrue directly. Mitigations: 15 min JWT, "password changed" email, short sessions.
Lost password (owner decision): staff and super admin passwords are reset only from the Supabase dashboard by the super admin/owner; no API endpoint sets another user's password.
Rejected: MFA/TOTP for super admin (revisit in phase 7); Send Email hook dropping emails (more code, the token hook already covers it).
Consequences: staff/super_admin created through the admin API must be created email-confirmed (`email_confirm: true`), otherwise a password set before confirmation is not recorded in `app.password_set`; staff email changes go through super_admin or the admin API, because the `email_change` link is a link login and the hook refuses it. Supabase still sends magic link/recovery emails to staff, but the link yields no session; the `/accedi` UI shows the password form for staff.

### ADR-035 PostgREST/GraphQL expose only an empty schema
Context: reinforces ADR-003; removing only `public` still exposes `graphql_public` and any future schema.
Decision: `[api] schemas = ["api"]` in `api/supabase/config.toml`, where `api` is an empty schema with no objects or grants (`schemas = []` makes PostgREST fall back to `public`); the same setting is applied by hand in the dashboard (API settings → Exposed schemas only the empty `api` schema, GraphQL off) of both remote projects (phase 8 checklist).
Consequences: no Data API surface at all; the publishable key alone can reach only Auth and Storage.
