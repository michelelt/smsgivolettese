# Decisions (ADR)

Format: context · decision · consequences. Status "accepted" unless marked.

### ADR-001 Identifier language

Context: brief mixes Italian/English names; CLAUDE.md says code in English; brief mandates `app_role` values incl. `volontario`.
Decision: tables/columns/functions in English (glossary in `data-model.md`, aligned with `smsg-context`); enum **values** in Italian exactly as in the brief.
Consequences: SQL/TS read naturally; enum values map 1:1 to UI labels and the brief; no translation layer for statuses.

### ADR-002 API queries run under the caller's Postgres role

Context: postgres.js on the pooler connects as a privileged user, which bypasses RLS, so RLS would not be a second line of defence.
Decision: every request query runs in a transaction that sets `request.jwt.claims`, `role` (`authenticated`/`anon`) and `app.request_id` with `set_config(..., true)`; service mode only for cron, invites, bootstrap, rate limit. `prepare: false` (transaction pooler).
Consequences: RLS and `auth.uid()` work in policies, triggers and audit; one extra round-trip per request; every DB call must go through `db.asUser/asAnon/asService`.

### ADR-003 Supabase Data API not used

Context: the web never queries tables; the publishable key is public, so PostgREST would expose a second write path that skips Turnstile/Zod.
Decision: remove `public` from exposed schemas (Data API off) in both projects; helpers in non-exposed schema `app`.
Consequences: smaller attack surface; anon policies still matter because the API runs public reads as `anon`.

### ADR-004 Volunteer overlap via `volunteer_commitments` + exclusion constraint

Context: brief allows a view/materialized table of commitments or a trigger.
Decision: real table maintained by security-definer triggers on `shift_assignments`, `shifts`, `transports`, with `exclude using gist (volunteer_id with =, period with &&)`.
Consequences: race-free (a trigger-only check races under READ COMMITTED; a matview cannot reject writes); one error code (23P01) for all conflicts; small denormalisation kept in sync in the same transaction.

### ADR-005 One role per user; min-role permission map

Decision: `user_roles.user_id` is the PK; `app_role` enum ordered `volontario < staff < super_admin`; `permissions.ts` maps action → minimum role; SQL `app.has_role(min)` mirrors it.
Consequences: hierarchy is trivial to check in TS and SQL; an action that is not monotonic in the hierarchy would need a different model (none today).

### ADR-006 Public writes through definer functions; client matching (booking part superseded by ADR-043, clients removed by ADR-060)

Context: no account for public users; anon must not get table insert rights.
Decision: `submit_public_booking` / `submit_post_proposal` (granted to anon) called by the API after Turnstile + rate limit. Booking attaches to an existing client by normalised phone + last name, never updating that client; otherwise creates one.
Consequences: no anonymous overwrites; possible duplicates are fixed by staff (merge not in scope).

### ADR-007 Settings split

Decision: `site_settings` (public, anon-readable) and `org_settings` (issuer data, stamp duty, fee amount, card counter, video limit; super_admin only), both single-row.
Consequences: anon select on a whole row is safe; fiscal/config data stays private.

### ADR-008 Invoices: immutable snapshot, PDF on demand

Decision: invoices snapshot issuer/customer/amounts; triggers allow only pay/void transitions; no deletes; `bookings.invoice_id` marks the current invoice (cleared on void); PDFs (invoice, receipt, travel sheet) generated by `pdfkit` per request, not stored. Credit notes out of scope (prototype copy).
Consequences: deterministic re-rendering; no storage of documents; voided numbers stay in sequence.

### ADR-009 Money in integer cents

Context: project convention (`smsg-context`).
Decision: all amounts `int` cents, including stamp threshold (7747) and amount (200).
Consequences: no float/rounding issues; conversion only at UI/PDF/CSV.

### ADR-010 Storage

Decision: public bucket `media` (uuid paths, 50 MB limit = Supabase free cap) and private bucket `proposals`; `media` row created only after the API verifies the uploaded object; orphan cleanup in daily cron.
Consequences: drafts' images are reachable only by unguessable URL; configurable video limit cannot exceed 50 MB on the free plan.

### ADR-011 Revalidation webhook path

Context: `/api/*` on the web domain is rewritten to the API.
Decision: web route `/hooks/revalidate`, shared secret header, tags `posts`, `post:<slug>`, `services`, `site-settings`; 1 h time-based fallback.
Consequences: no route collision; a missed webhook self-heals within an hour.

### ADR-012 Rate limiting in Postgres

Decision: `rate_limit_hits` table + `app.consume_rate_limit()`; IP from Vercel headers.
Consequences: no extra service; to verify the client IP survives the web rewrite (phase 3), fallback Vercel Firewall rule.

### ADR-013 Time zone

Decision: instants `timestamptz`; availability, slots, invoice year and "tomorrow" computed in `Europe/Rome`; cron schedules in UTC.
Consequences: DST handled by Postgres; reminder time drifts by 1 h between summer/winter (acceptable).

### ADR-014 Volunteer data minimisation and writes

Decision: volunteers read transports only via view `volunteer_transports_v` (+ strict Zod response); their writes on shifts/transports/profile go through definer functions; availability uses plain own-row RLS.
Consequences: column-level restriction without per-role grants (all users share Postgres role `authenticated`).

### ADR-015 Transport timing

Decision: `departure_at`, addresses nullable while `richiesto` (public bookings lack them); required from `assegnato`. Busy period = departure → return, else appointment + 1 h, else departure + 2 h.
Consequences: public bookings can create transports; overlap check is approximate when no return time is given.

### ADR-016 Assignment candidates and absences

Context: brief says staff see "only available volunteers" but also labels "già impegnato" and "assente".
Decision: dialog lists all active volunteers, available first (sorted by shifts this month); "già impegnato"/"assente" are shown disabled. API rejects absent volunteers (409 `VOLUNTEER_ABSENT`); overlap is rejected by the DB.
Consequences: staff understand why someone is not selectable; volunteers with no declared availability can still be assigned (shown last, label "non indicata").

### ADR-017 Migrations and deploy order

Decision: API `main`: tests → `supabase db push` (prod) → `vercel deploy --prebuilt --prod`, with Vercel Git auto-deploy for `main` disabled in the API project. PRs with migrations push to staging; staging can be reset.
Consequences: DB always migrated before code; staging may hold migrations of unmerged PRs (reset when needed).

### ADR-018 OpenAPI contract check

Decision: committed `openapi.json`, CI regenerates (must match) and runs `oasdiff breaking` vs `main`; web commits generated `lib/api/schema.d.ts`.
Consequences: breaking changes need a major bump; backward-compatible changes make repo deploy order irrelevant.

### ADR-019 Audit via triggers (clients removed by ADR-060)

Decision: generic `app.audit()` trigger on services, site_settings, members, fees, invoices, lines, counters, roles, profiles, volunteers, shifts, assignments, transports, org_settings; actor from JWT claims; GDPR anonymisation redacts affected rows.
Consequences: SQL-function writes are audited too; audit table grows (no retention purge yet).

### ADR-020 Auth details

Decision: JWT verified with `jose` + Supabase JWKS; new key names (`sb_publishable_…`, `sb_secret_…`; legacy anon/service_role work identically); sign-ups disabled; Resend as Auth SMTP; JWT lifetime 15 min; profiles created by the API (no profile trigger on `auth.users`; see ADR-034 for the password_set trigger).
Consequences: deactivation/role change takes effect within 15 min.

### ADR-021 Next.js 16 `proxy.ts`

Context: brief names `middleware.ts`; Next 16 renamed it `proxy.ts`.
Decision: use `proxy.ts` (same role).
Consequences: none functional; update brief references mentally.

### ADR-022 Block editor rendering

Decision: BlockNote in the editor; content stored as BlockNote JSON; custom blocks for gallery, video embed, button, divider where BlockNote lacks them; Zod whitelist on write; small own server renderer (switch per block type → React + `next/image`), not BlockNote's HTML export.
Consequences: full control over accessibility/images; renderer must be extended when a block type is added.

### ADR-023 Prototype features dropped (moot for bookings since ADR-043)

Context: prototype shows "Le mie prenotazioni", self-cancel and "Le sue proposte", which require an identity; brief says no account for the public.
Decision: not implemented; success screens tell people they will be called back; cancellations by phone.
Consequences: simpler public flow; no public personal data exposure.

### ADR-024 Reminders idempotency

Decision: `reminder_sent_at` on `shift_assignments` and `transports`, set after a successful send; single daily cron (`0 16 * * *` UTC).
Consequences: retries never double-send; works on Vercel Hobby cron limits.

### ADR-025 Counters adjustable upward only

Context: prototype lets staff edit the "last card number"; super_admin owns "numerazioni".
Decision: `set_member_counter` / `set_invoice_counter` (super_admin) only accept values ≥ the highest assigned number.
Consequences: migration from the old register is possible; numbers can never be reissued.

### ADR-026 GDPR retention

Decision: anonymisation keeps invoices (fiscal 10-year retention) and card numbers; personal fields nulled elsewhere.
Consequences: needs confirmation by the association's privacy officer (open question).

### ADR-027 Local secrets file and super admin password

Decision: workspace `secrets.env` (git-ignored, `chmod 600`, template `secrets.env.example`) holds `SUPERADMIN_EMAIL`, `SUPERADMIN_PASSWORD`, `SUPABASE_DB_PASSWORD_{STAGING,PROD}`; Makefile sources it. The super admin password from the file is set only when the account is created; afterwards only the super admin can change it (self-service with reauthentication). Claude Code is denied reading the file.
Consequences: the file password goes stale after the first change (expected); a forgotten password is reset from the Supabase dashboard; CI keeps using GitHub secrets.

### ADR-028 Submodules created in place with relative URLs

Context: no remotes may be added or pushed; a fresh clone must work once the owner pushes.
Decision: `git init -b main` inside `api/` and `web/`, commit, then `git submodule add ../smsg-api api` / `../smsg-web web` (git adopts the existing repo; no clone, no remote). `.gitmodules` URLs are relative, so they resolve against the workspace's GitHub URL once pushed (all three repos under the same owner, named `smsg-api`, `smsg-web`).
Consequences: zero remote config now; the owner must push api/web before the workspace (pinned SHAs must exist); a local fresh-clone test needs `git -c submodule.api.url=<abs>/api ...` overrides.

### ADR-029 Default branch `main` everywhere

Decision: new repos `git init -b main`; workspace renamed locally `git branch -m master main` (safe: no remote). API `staging` branch created in the phase that needs it.
Consequences: matches CI triggers (`main` = production) and ADR-017.

### ADR-030 `make dev` process runner

Decision: `pnpm dlx concurrently@<exact 9.x> -k -n api,web -c blue,magenta "pnpm -C api dev" "pnpm -C web dev"`; no workspace package.json.
Consequences: prefixed coloured output and Ctrl+C/kill-others for free; first run downloads the tool (cached afterwards).

### ADR-031 Toolchain and local API entrypoint

Decision: Node 24 (`.nvmrc`, `engines`), `packageManager: pnpm@12.9.1` in each repo, caret ranges + committed lockfile, CI `--frozen-lockfile`. Latest stable majors at scaffold time: Next 16, React 19, Tailwind 4 (`@tailwindcss/postcss`, tokens via `@theme`), Hono 4 + `@hono/zod-openapi` + Zod 4, Vitest, TypeScript strict, ESLint 9 flat config (`eslint` CLI; `next lint` is gone in 16) + Prettier. API: `api/index.ts` (Vercel) and `src/server.ts` (local only, `@hono/node-server` on :3001, run with `tsx watch`) both import `src/app.ts`. No `vercel dev`.
Consequences: no Vercel login for local dev; confirm in phase 8 that Vercel's build image supports pnpm 12 (else pin the newest supported major).

### ADR-032 Local env files

Decision: `make setup` copies each repo's `.env.example` → `.env.local` only if missing (hand-edited). `make dev`, after `supabase start` (run in `api/`), regenerates `.env.development.local` in api and web from `supabase status -o env` (Supabase URL, keys, DB URL only; mapped to our names). Next loads it natively with precedence over `.env.local`; API loads both via `node --env-file-if-exists` (generated first, then `.env.local`). Supabase CLI config lives only in `api/supabase/`; workspace root `supabase/` (CLI link cache only) is deleted.
Consequences: local keys are never typed by hand or committed; both env files git-ignored.

### ADR-033 OpenAPI generation from the exported file

Context: `make dev` must regenerate the web client before the API is running.
Decision: `pnpm -C api openapi:export` writes `api/openapi.json` by importing the app (no server); `make gen-api` = export, then `OPENAPI_URL=../api/openapi.json pnpm -C web gen:api`.
Consequences: no start-up race; web CI still uses the committed `schema.d.ts`.

### ADR-034 Staff and super admin cannot sign in with magic link or recovery

Context: phase 2 security review; an emailed link (magic link/OTP, recovery) would let anyone with access to a staff mailbox get a privileged session without the password.
Decision (approved by the owner): the Custom Access Token Hook returns an error (no token) when `app_role ∈ {staff, super_admin}`, the account has a recorded password (`app.password_set`), and `authentication_method` or any `amr` method is not `password`/`token_refresh`. GoTrue reports magic link, recovery, invite and email OTP all as `otp`, and GoTrue sets a random password while verifying an invite, so the hook relies on `app.password_set` (a row written by a trigger on `auth.users` when a confirmed user sets a password, or a user is created with one); without that row a link session is issued without `app_role` and can only set the first password; a link-born session also loses refresh once a password exists, so after setting the first password staff sign in again with email and password; volunteers keep magic link + recovery (elderly-friendly). Own password change in `/gestione` always does `reauthenticate()` + emailed nonce in the UI.
Residual risk (accepted): GoTrue `secure_password_change` enforces the nonce server-side only for sessions older than 24 h, so a stolen fresh session could change the password calling GoTrue directly. Mitigations: 15 min JWT, "password changed" email, short sessions.
Lost password (owner decision): staff and super admin passwords are reset only from the Supabase dashboard by the super admin/owner; no API endpoint sets another user's password.
Rejected: MFA/TOTP for super admin (added in phase 7, ADR-063); Send Email hook dropping emails (more code, the token hook already covers it).
Consequences: staff/super_admin created through the admin API must be created email-confirmed (`email_confirm: true`), otherwise a password set before confirmation is not recorded in `app.password_set`; staff email changes go through super_admin or the admin API, because the `email_change` link is a link login and the hook refuses it. Supabase still sends magic link/recovery emails to staff, but the link yields no session; the `/accedi` UI shows the password form for staff.

### ADR-035 PostgREST/GraphQL expose only an empty schema

Context: reinforces ADR-003; removing only `public` still exposes `graphql_public` and any future schema.
Decision: `[api] schemas = ["api"]` in `api/supabase/config.toml`, where `api` is an empty schema with no objects or grants (`schemas = []` makes PostgREST fall back to `public`); the same setting is applied by hand in the dashboard (API settings → Exposed schemas only the empty `api` schema, GraphQL off) of both remote projects (phase 8 checklist).
Consequences: no Data API surface at all; the publishable key alone can reach only Auth and Storage.

### ADR-036 CSP: static on public pages, nonce on private pages

Context: a nonce CSP forces dynamic rendering and breaks ISR; Next's inline flight scripts vary per page, so hashes cannot cover them. Phase 1 deferred "full CSP with nonces".
Decision: public routes get a static CSP from `next.config.ts` headers (source `/:path((?!gestione|accedi|imposta-password).*)`): `default-src 'self'; script-src 'self' 'unsafe-inline' https://challenges.cloudflare.com; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: <SUPABASE_URL>; connect-src 'self' <SUPABASE_URL>; frame-src https://challenges.cloudflare.com; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'` (+ `'unsafe-eval'` in dev only; `upgrade-insecure-requests` in prod only). `/gestione/**`, `/accedi`, `/imposta-password` get the same policy built per request in `proxy.ts`, but `script-src 'self' 'nonce-<random>' 'sha256-<text-size script>'` (no `unsafe-inline`), set on request and response headers so Next applies the nonce. YouTube/Vimeo frames added in phase 6.
Consequences: ISR kept; the nonce intent is kept where sessions and personal data live; public pages rely on React escaping + the block whitelist (ADR-022) for XSS; the public CSP must never contain a hash or nonce (that would disable `'unsafe-inline'` and break Next).

### ADR-037 Text size persisted in localStorage, applied before paint

Decision: A/A+/A++ stored in `localStorage["text-size"]` (`m|l|xl`); a fixed inline script in the root layout `<head>` sets `document.documentElement.dataset.textSize` before paint; CSS sizes `html` from that attribute (default 19px). Script text is one exported constant; its sha256 goes into the private CSP (ADR-036).
Consequences: pages stay static (no cookie read); no flash; per device, which is what elderly users expect.

### ADR-038 Home "prossimi appuntamenti" deferred to phase 6 (superseded by ADR-043)

Decision: phase 3 home has no appointments block (no placeholder); phase 6 adds it from published posts (`evento`, `event_date >= today`). Services' `schedule_note` stays on service cards only.
Consequences: no throwaway data source; home = intro, services, "Prenotare in tre passi", phone.

### ADR-039 Public API contract (phase 3) (superseded by ADR-044)

Decision: JSON fields camelCase. `GET /public/services` → `{ items: [{ id, name, description, memberPriceCents, nonMemberPriceCents, scheduleNote, bookable, requiresTransport }] }` (active, by `sort_order, name`). `GET /public/site-settings` → `{ phone, email, address, openingHours, slogan, homeIntro, membershipInfo }`. `POST /public/bookings` body `{ serviceId, day (YYYY-MM-DD), slot (mattina|pomeriggio), firstName, lastName, phone, declaredMember, notes? (≤ 600), turnstileToken }` → 201 `{ id }`. No tax code online (collected by staff at invoicing) and no consent checkbox (art. 6.1.b GDPR: a short notice with a link to `/privacy` above the confirm button). Phone: strip spaces `.-/()`, drop `+39`/`0039`, then must match `^(0\d{5,10}|3\d{8,9})$`; the API passes the normalised national form so client matching works. Order: Zod → rate limit → Turnstile → `submit_public_booking`. Errors: 400 `VALIDATION_ERROR`, 400 `TURNSTILE_FAILED` (also for an empty token, without calling Cloudflare), 429 `RATE_LIMITED`, 422 `INVALID_DAY` / `SERVICE_NOT_BOOKABLE`.
Consequences: the rate limit counts failed attempts too; the Turnstile failure e2e blanks the token via `page.route`.

### ADR-040 Client IP through the web proxy (rate key amended by ADR-043)

Context: on Vercel the API sees the web deployment, not the browser, behind the external rewrite.
Decision: `proxy.ts` also matches `/api/public/:path*` and does `NextResponse.rewrite(API_URL + path, { request: { headers } })` with `x-client-ip` = first `x-forwarded-for` entry (else `x-real-ip`, else `local`) and `x-proxy-secret: API_PROXY_SECRET` (both overwrite incoming values). The API trusts `x-client-ip` only with a constant-time-equal secret; otherwise it uses `x-real-ip`, first `x-forwarded-for`, else `local`. Rate key `booking:<ip>`, 5 per 600 s.
Consequences: one new secret in both repos; direct API callers cannot spoof the IP; locally all requests may share one bucket (tests clear `rate_limit_hits` first).

### ADR-041 Booking days: no capacity model (superseded by ADR-043)

Decision: the wizard offers the next 12 non-Sunday days from tomorrow (Europe/Rome) as in the prototype; the DB allows tomorrow..+60, no Sunday. No capacity, holidays or closed days: staff confirm the time by phone.
Consequences: overbooking is handled by staff calling back; a closed-days list can be added later if staff ask.

### ADR-042 PWA without service worker

Decision: `public/manifest.webmanifest` (name, short_name, `start_url: "/"` (user choice: public visitors may install it too; volunteers reach `/gestione` from the menu), `scope: "/"`, `display: standalone`, brand colours) + 192/512 and maskable icons + apple-touch-icon. No service worker, no offline cache.
Consequences: installable on phones for volunteers; never serves stale bookings/shifts; no SW update bugs to maintain.

### ADR-043 Public site is a showcase; bookings are staff-only (bookings removed by ADR-070)

Context: owner requirement 2026-10-16 (overrides brief "Sito pubblico" and phase 3 as shipped): site modelled on sms-sangilliese.org; no public element may point to phone calls or price lists; all bookings entered by staff.
Decision: remove `POST /public/bookings`, the `/prenota` wizard and the phone bar; a new migration drops `submit_public_booking` (drop, not revoke: no caller left). Transport auto-creation moves to an AFTER INSERT trigger `bookings_create_transport` on `bookings` (security invoker: staff already have I on `transports`) that inserts a `richiesto` transport (`booking_id`, `client_id`, `travel_date = day`) when the service `requires_transport`; phase 4 staff bookings are plain inserts. `services.bookable` dropped (no wizard). Enum value `booking_origin.online` kept unused (dropping enum values is costly).
Menu: Home, Chi siamo, Servizi, Convenzioni, Dove siamo (+ Privacy in footer); Eventi e novità (`/notizie`) and Galleria appear in phase 6, hidden until then with no placeholders. Phase 3 home = intro (slogan + `home_intro`, e.g. art. 1 law 3818/1886), link to Servizi, Dove siamo address. Phase 6 home adds upcoming events, link to all news, gallery carousel; Galleria = cover images of published posts linking to the post (no new table).
Kept for "Proponi una notizia" (phase 6): Turnstile web component, API `turnstile`, client-IP (ADR-040) and rate-limit libs, Turnstile in the public CSP; rate key becomes `proposal:<ip>`, 3 per 3600 s. PWA `start_url` stays `/`. Text size and accessibility goals unchanged.
Supersedes ADR-038, ADR-041, the booking part of ADR-006 and ADR-023; ADR-015 nullable times/addresses now serve staff-created `richiesto` transports.
Consequences: no anonymous write path until phase 6; staff must enter every booking (by phone or at the desk).

### ADR-044 Public content and API contract without prices or contacts (price column amended by ADR-060, dropped by ADR-070)

Decision: prices stay in `services.price_cents` (single member price since ADR-060; staff, invoices) but anon gets column-level select only on `services (id, name, description, schedule_note, sort_order, active)`, so price leaks fail in the DB too. `site_settings` drops `phone`, `email`, `opening_hours`, `membership_info` (no public consumer; avoids a quota price on the site) and adds `vat_number text`, `conventions jsonb not null default '[]'` (`[{ title, description, url? }]`) and `footer_links jsonb not null default '[]'` (`[{ group: associazioni|mutuo_soccorso|utili, label, url }]`), both `check (jsonb_typeof(..) = 'array')`, items validated by Zod on write (https URLs only). Smallest option: no new tables; ADR-007 "whole row is public" stays true.
Contract (supersedes ADR-039): `GET /public/services` → `{ items: [{ id, name, description, scheduleNote }] }`; `GET /public/site-settings` → `{ address, slogan, homeIntro, vatNumber, conventions, footerLinks }`; strict Zod response schemas. Major `info.version` bump (ADR-018).
Consequences: Convenzioni and footer lists are edited by staff in "site info" (phase 4), seeded until then; downloadable per-service PDFs (reference site) are out of scope until asked.

### ADR-045 Staff API conventions (phase 4 onwards)

Context: first staff modules; later phases should copy the same shape.
Decision: JSON camelCase; dates `YYYY-MM-DD`, times `HH:MM`, money `*Cents` int. Lists: `?page=1&pageSize=50` (max 100) → `{ items, total }` (`src/lib/pagination.ts`); `q` = case-insensitive contains. Edits `PATCH`; state changes `POST /<res>/:id/<verb>` as conditional UPDATEs (`where id = $1 and status in (…)`): 0 rows → 404 if the row is missing, else 409 `<RES>_INVALID_TRANSITION`. No DELETE endpoints (services deactivate, bookings cancel, invoices void). `:id` = `z.uuid()`; static paths (`/kpis`, `/export.csv`) registered before `/:id`. Files: `application/pdf` / `text/csv; charset=utf-8`, `Content-Disposition: attachment`, `Cache-Control: no-store`. `23505` mapped by constraint name in `errors.ts`, new `P0001` codes added to `PG_RAISE`, `23514` → 400 `VALIDATION_ERROR`. Additive changes → minor `info.version` bump.
Consequences: one pattern to learn; status rules live in the service (unit-tested), RLS still limits who writes.

### ADR-046 Booking lifecycle; transport sync on cancel/restore (superseded by ADR-070: no bookings)

Context: roadmap left open whether `bookings_create_transport` gets an update branch.
Decision: create → `origin = 'telefono'` (desk too, no new enum value), `status = time ? 'confermata' : 'attesa'`. confirm `attesa→confermata` (time optional, as the prototype); execute `attesa|confermata→eseguita` (`executed_at = now()`); cancel `attesa|confermata→annullata` (`cancelled_by` `staff|utente`); restore `annullata→attesa` (time kept). Client, service, day, slot and price are immutable after creation (cancel and re-create): no endpoint, so no trigger branch for them. New AFTER UPDATE OF status trigger `bookings_sync_transport` (security invoker): to `annullata` → linked transport `annullato` unless `svolto|annullato`; from `annullata` → an `annullato` linked transport back to `richiesto` with driver and vehicle cleared.
Chosen over manual reconciliation: a forgotten transport sends a volunteer out for nothing. Consequences: commitments freed by the existing transport trigger; no driver email until phase 5 (add it there); an edit endpoint must extend the trigger.

### ADR-047 Price at booking (superseded by ADR-060: `price_applied_cents` = `services.price_cents` snapshot, no `declared_member`)

Decision: `declared_member` = body `declaredMember` when sent, else "client linked to an `attivo` member"; `price_applied_cents` = that service price, snapshotted. Inactive service → 422 `SERVICE_INACTIVE`. Payment of the current year's fee is not considered.
Consequences: staff can apply the member price to someone not yet linked (prototype "Socio" checkbox); price changes never touch existing bookings.

### ADR-048 Tax code validation in the API only

Decision: `api/src/lib/tax-code.ts`: normalise (trim, upper, drop spaces); hard rule `^[A-Z0-9]{16}$` (= DB check, 400); soft rule = official layout incl. omocodia + check character → 422 `TAX_CODE_INVALID` (`details.field`) unless the body has `taxCodeConfirmed: true`. Used by members and invoice issue (clients removed, ADR-060). The web does not duplicate the algorithm: on 422 it shows the warning and a "Salva comunque" button that resubmits with the flag.
Consequences: one unit-tested implementation; one extra round trip only when the code looks wrong.

### ADR-049 PDFs and staff-readable issuer data

Consequences: unreferenced `media` rows (removed from content) stay until a media library is asked for; proposals emails to staff not sent (nav badge instead); Safari < 17 uploads JPEG.

### ADR-063 Super admin TOTP MFA, switchable per deployment (revisits ADR-034)

Context: owner decision: MFA now, but on/off per deployment; owner demos as super admin, then hands over to the real one.
Decision: Supabase Auth MFA TOTP (`[auth.mfa.totp] enroll_enabled = verify_enabled = true` in `config.toml`). API env `SUPERADMIN_MFA=off|required` (Zod in `src/config/env.ts`, default `off` outside production, no default in production, like `RESEND_API_KEY`). One enforcement point, `authenticate` (`src/auth/middleware.ts`): when `required`, `role = super_admin` and JWT `aal ≠ aal2`, `user.role` becomes `staff` and `user.mfaPending = true`; since `ctx.ts` builds DB claims from `user.role`, RLS and definer functions see staff too (no SQL toggle). `requirePermission` on an action whose minimum is `super_admin` with `mfaPending` → 403 `MFA_REQUIRED`. Hook (`app.custom_access_token_hook`): allowed methods become `password`, `token_refresh`, `totp`, `mfa/totp` (an `otp` entry still refuses staff/super_admin).
Web (no env var): after password sign-in, `mfa.getAuthenticatorAssuranceLevel()` with `nextLevel = aal2 > currentLevel` → `/accedi/verifica` (6-digit code, `challengeAndVerify`, then `next`); `/gestione/account/sicurezza` (any role reaches `account`, shown in the menu to super_admin only): enrol (QR + secret text, verify), list, remove own factor (needs aal2); `lib/api/client.ts` middleware: 403 `MFA_REQUIRED` → `/gestione/account/sicurezza?next=…` with "Per questa sezione serve il codice dell'app di autenticazione". Once a factor is verified, sign-in always asks for the code, even with `off`.
Lost device: `DELETE /users/:id/mfa` (new permission `users.reset_mfa`, super_admin at aal2, not self → 409 `SELF_FORBIDDEN`) deletes every factor via `auth.admin.mfa.listFactors/deleteFactor`; if no other super admin exists, the owner deletes the factor in the Supabase dashboard (same rule as ADR-034 passwords). No recovery codes (Supabase has none); the page suggests enrolling a second device.
Handover: demo super admin invites the real one (`POST /users/invite` role `super_admin`) → they set a password at `/imposta-password`, sign in, enrol TOTP → the real super admin deactivates the demo account (ADR-064; never deleted, it stays as audit actor).
Consequences: aal1 super admin works as staff; tested by API unit tests (aal1/aal2 tokens) and a real-Auth test that password + TOTP gets a token with `app_role`.

### ADR-064 Users and roles lifecycle

Decision: `GET /users?role&active&q&page&pageSize` (`users.read`) → `{id, firstName, lastName, email, phone, role, active, anonymizedAt}`; `POST /users/invite` now accepts `staff|super_admin` when `can(role, 'users.invite_staff')`, else 403. `PATCH /users/:id {role}` (`users.change_role`): becoming `volontario` upserts `volunteers` (active), leaving it sets `volunteers.active = false` (existing `DRIVER_HAS_FUTURE_TRANSPORTS` → 409). `POST /users/:id/deactivate` / `/reactivate` (`users.deactivate`): inside the same `asUser` tx, conditional UPDATE of `profiles.active` (+ `volunteers.active = false` on deactivate), then `auth.admin.updateUserById(id, {ban_duration: '876000h' | 'none'})`; an Auth error throws and rolls back. Proxy: a `/gestione*` request with a valid session but no `app_role` (invited staff without password) redirects to `/imposta-password`, not `/accedi`.
Web: `/gestione/utenti-e-ruoli` (list, invite dialog, role select, deactivate/reactivate, "Azzera autenticazione a due fattori").
Consequences: deactivation is immediate for refresh, ≤ 15 min for live JWTs (ADR-020); accepted: an already issued JWT stays valid up to 900 s after the ban (no revocation). `DELETE /users/:id/mfa` writes an `audit_log` row (`profiles`, `after {mfaReset, removed}`) in service mode with the caller as actor. Anonymised users cannot change role or be reactivated (`USER_INVALID_TRANSITION`).

### ADR-066 Audit log viewer, coverage, append-only with redaction

### ADR-067 GDPR export and anonymisation (details of ADR-026; bookings parts removed by ADR-070)

Decision: two definer functions, one transaction each, `app.require_role('super_admin')`, granted to `authenticated`: `app.gdpr_export(p_subject text, p_id uuid) returns jsonb` (also inserts an `export` audit row) and `app.anonymize_member(p_id)` / `app.anonymize_user(p_id) returns jsonb` (`{retainedInvoices[{id, year, number}]}`); a second call on an anonymised subject is a no-op.
Export (`GET /gdpr/export?subject=member|user&id=`, JSON attachment `dati-socio-<card>-AAAA-MM-GG.json` / `dati-utente-AAAA-MM-GG.json`, `no-store`): member → `{subject, exportedAt, member, membershipFees, bookings, transports, invoices[+lines]}`; user → `{…, profile, role, volunteer, availabilityRules, availabilityExceptions, shiftAssignments[+shift times/type], transportsAsDriver[id, travelDate, status, km, driverNotes]}` (never other people's data).
Member (must be `cessato`, else 409 `MEMBER_ACTIVE`): names `Anonimo`, `tax_code, birth_date, birth_place, address, postal_code, city, phone, email, notes` null; `bookings.notes` null; transports `requested_by, reason, notes, driver_notes` null, `from_address`/`to_address` = `'(anonimizzato)'` (check needs them from `assegnato`); fees, card number, amounts, statuses, invoices untouched.
User (not self → 409 `SELF_FORBIDDEN`): profile names `Anonimo`, phone null, email `deleted+<id>@invalid.local`, `active = false` (last super admin guard applies); volunteer `can_drive = false`, licence/notes null, `active = false` (`DRIVER_HAS_FUTURE_TRANSPORTS` → 409); delete availability rules/exceptions and future `proposto|confermato` assignments; delete `app.password_set` row. After commit the API calls `auth.admin.updateUserById(id, {email, email_confirm: true, ban_duration: '876000h', user_metadata: {}})`; on failure 502 `AUTH_SYNC_FAILED`, the user retries (idempotent). Auth users are never deleted (`profiles` FK restrict).
Audit redaction (last step, so it covers the rows the anonymisation itself just wrote): `redacted = true, before = after = null` where (`table_name = 'members'` and `row_id = id`) or (`table_name in ('membership_fees','transports')` and `member_id` in before/after = id) for members; `table_name in ('profiles','volunteers','user_roles')` and `row_id = id` for users. Invoice audit rows kept (ADR-026).
Web: SA-only "Esporta dati" and "Anonimizza" on `/gestione/soci/[id]` and in `/gestione/utenti-e-ruoli`; anonymise dialog requires typing `ANONIMIZZA` and lists retained invoices afterwards.
Consequences: a cessato member's non-final bookings/transports remain (redacted); privacy officer confirmation still open.
