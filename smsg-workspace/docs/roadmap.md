# Roadmap

Rules: one phase at a time; a phase is done when `make test` is green, `security-reviewer` has no open high/medium findings, and each touched repo has a Conventional Commit (workspace submodule pointers updated). End each phase with a short summary: what works, how to try it, what's left.

## 1. Workspace, scaffolding, CI
- **Scope**: `smsg-workspace` (Makefile, `.env.example`, README for non-expert volunteers, submodules), `smsg-api` (Hono + `@hono/zod-openapi`, `api/index.ts`, `config/env.ts`, `lib/logger.ts`, `lib/errors.ts`, error handler, `GET /health`, `GET /openapi.json`, Supabase CLI config), `smsg-web` (Next.js, Tailwind tokens: bordeaux `#7A1E2C`, blu `#1F3F7A`, 19px base; "hello" page; `/api` rewrite; generated client).
- **Deliverables**: all Makefile targets (`setup`, `dev`, `test`, `db-reset`, `gen-api`, `superadmin` stub, `deploy-check`), ESLint + Prettier, GitHub Actions (lint, typecheck, test, openapi diff), `.env.example` per repo; Makefile sources workspace `secrets.env` when present (ADR-027) and never prints its values.
- **Acceptance**: `make setup && make dev` from a fresh clone shows the hello page on :3000 calling `/api/health` → 200 via rewrite; `make test` green (1 unit test per repo); CI green on both repos; `openapi.json` committed and checked.
- **Repos**: workspace, api, web.

## 2. Schema, RLS, Auth Hook, super admin, login
- **Scope**: full schema of `data-model.md` (all tables, enums, constraints, triggers, SQL functions, views, audit triggers, storage buckets), all RLS policies of `permissions.md`, Custom Access Token Hook, `permissions.ts` + `requirePermission`, JWT verification (JWKS), `db.asUser/asAnon/asService`, `scripts/bootstrap-superadmin.ts`, seed with obvious demo data ("Mario Rossi (esempio)"). Web: `/accedi`, `/imposta-password`, magic link, `proxy.ts` guard, role-aware `/gestione` shell.
- **Acceptance**: RLS integration tests per role (anon/volontario/staff/super_admin × each table: allowed and denied S/I/U/D); invariant tests: overlapping commitments → 23P01, ineligible driver rejected, invoice/member numbering under 10 concurrent calls has no gaps or duplicates, void keeps number, `(member_id, year)` unique, last super admin protected; hook puts `app_role` in JWT; `make superadmin` idempotent (credentials from `secrets.env`, password never overwritten on re-run); super admin changes own password with reauthentication and no other user or endpoint can change it; Playwright: staff login reaches `/gestione`, volunteer blocked from staff pages.
- **Repos**: api, web, workspace.

## 3. Public showcase site (rework per ADR-043/044)
- **Scope**: showcase only, no booking, no phone/email, no prices. Pages: home (intro, link to Servizi, Dove siamo), chi-siamo, servizi (descriptive), convenzioni (from `site_settings.conventions`), dove-siamo (address only), privacy (placeholders); footer with link groups (`footer_links`), VAT number, Privacy; text size A/A+/A++ remembered, large-button menu; ISR + `/hooks/revalidate`; SEO (metadata, sitemap, OG); PWA manifest; CSP. Remove `/prenota`, `/contatti`, phone bar, `POST /public/bookings`, `submit_public_booking`, `services.bookable`; add trigger `bookings_create_transport`. Turnstile, client-IP and rate-limit code stay for phase 6.
- **Acceptance**: Playwright on every public page: no `a[href^="tel:"]`, no `a[href^="mailto:"]`, no `€`; `/prenota` → 404; RLS test: anon cannot select price columns of `services` (42501) and `submit_public_booking` no longer exists; trigger test: a staff-inserted booking for a `requires_transport` service creates one `richiesto` transport; API tests for the new public contract; Lighthouse Accessibility ≥ 95 and axe clean on all public pages; revalidation updates the services page without redeploy; client IP header unit-tested.
- **Repos**: api, web.

## 4. Staff: bookings, clients, members, invoices (clients removed by phase 5b, bookings by phase 7b)
- **Scope**: bookings list/filters/KPIs (confirm with time, executed, cancel, restore, phone/desk booking — the only way to book; transport services create a `richiesto` transport via trigger `bookings_create_transport`; cancel/restore sync it via `bookings_sync_transport`, booking client/service/day not editable, ADR-046), clients with history, members book (progressive card, CF validation with checksum + "save anyway", fees with PDF receipt, end/reactivate, CSV export), invoices (issue from executed bookings via `issue_invoice`, server PDF, mark paid, void, CSV export `;`-separated UTF-8 BOM), services & prices, site info (address, slogan, home intro, VAT number, convenzioni, footer links; Zod-validated jsonb, the only write path, plus a DB check on item URLs being https — `GET /public/site-settings` fails closed with 500 on any invalid item).
- **Contract**: ADR-045..052 (routes, CSV, PDF, tax code, site info at `/gestione/sito`).
- **Acceptance**: Vitest for services (price by member status, stamp duty at 77.47/77.48, numbering per year, void → bookings invoiceable again, number not reused, booking transitions, tax code checksum incl. omocodia, CSV escaping/BOM); DB tests: cancel/restore sync the transport, `site_settings_links_valid` rejects `http://`, `card_number` immutable, `staff_org_info` denied to volontario; Playwright: invoice issuance end to end; audit rows written for members/invoices.
- **Repos**: api, web.

## 5. Volunteers, availability, shifts, transports, notifications
- **Scope**: volunteers + vehicles registry, invites of volunteers by staff, volunteer UI (weekly grid Mon–Sat × Mattina/Pomeriggio + custom times, "Non ci sono", "I miei impegni" with Confermo/Non posso, map link), shifts weekly calendar (day view mobile, grid desktop), "copia la settimana", assignment dialog with candidates (labels disponibile/già impegnato/assente, sorted by shifts in month), coverage + uncovered count on dashboard, transports form/list day & week, driver + vehicle assignment, travel sheet PDF, close with km/notes, monthly CSV, Resend emails on assignment, daily cron reminders.
- **Acceptance**: forced overlap → 409 `COMMITMENT_OVERLAP`; volunteer cannot read transport columns outside the minimal set (RLS + API test); reminder cron idempotent; Playwright: create shift + assign, volunteer enters availability, volunteer confirms commitment.
- **Repos**: api, web.

## 5b. Members only (rework per ADR-060)
- **Scope**: migration `members_only` (drop `clients`; `member_id` on bookings/transports/invoices; `services.price_cents`; drop `declared_member`; `require_active_member` trigger; `issue_invoice(p_member_id…)`; `volunteer_transports_v` `member_*`; seed clients → members); API: remove `clients` module/permissions, `clientId` → `memberId`, `client*` → `member*`, `priceCents`, member detail history, major version; web: remove `/gestione/utenti`, member picker + inline "Nuovo socio" in booking/transport forms, history on `/gestione/soci/[id]`, single price on services.
- **Acceptance**: DB: insert booking/transport for a `cessato` member → `MEMBER_NOT_ACTIVE`, executing/invoicing an existing booking of a member ended later still works, `clients` absent, invoice snapshot address from member; API: 422 `MEMBER_NOT_ACTIVE`, `/clients` 404, member detail history, invoice tax code saved on member; volunteer view exposes only `member_first_name/last_name/phone`; Playwright: phone booking with a new member created inline.
- **Repos**: api, web.

## 5c. Editable public site (ADR-061)
- **Scope**: migration `site_pages` (`site_settings.pages` + `site_settings_pages_valid`, filled with today's hardcoded copy incl. privacy placeholders; `seed.sql` likewise); API: `PageTexts` strict Zod in `public.schemas.ts`, required in `PUT /site-settings`, returned by `GET /public/site-settings`, major bump; web: chi-siamo, privacy, servizi, convenzioni, dove-siamo, home read `pages` (privacy gets `revalidate = 3600`), page bodies extracted into `components/public/` with `ReactNode` slots + `preview`, `/gestione/sito` → "Modifica il sito" with tabs and one sticky save (PUT + PATCH `/services/:id` for name/description/schedule note, no prices), "Modifica questa pagina" client link in the public layout.
- **Acceptance**: DB: `pages` missing a key or not an object → `23514`, anon reads `pages`, volontario update denied, update writes an audit row; API: unknown page key/field, empty title, > 20 sections, body > 5000 → 400; valid PUT revalidates `site-settings`; Playwright: staff edits a Chi siamo paragraph, saves, sees it on `/chi-siamo`; edit link visible to staff, absent for anon.
- **Repos**: api, web.

## 6. Bacheca, block editor, media, moderation
- **Scope**: BlockNote editor (paragraph, heading, image with caption/size, gallery, video upload or YouTube/Vimeo, quote, list, button-link, divider), cover image, drafts, preview, publish/update, slug, signed uploads with browser resize to WebP ≤ 2000 px, video size limit with clear message, server renderer with whitelist + `next/image`, public "Eventi e novità" (`/notizie` list with filter + article page with lightbox) and "Galleria" (cover images of published posts) pages added to the menu; home sections: upcoming events (`evento`, `event_date >= today`) with "testo completo" links, link to all news, gallery carousel (ADR-043); public "Proponi una notizia" (Turnstile, rate key `proposal:<ip>`, photo, video link) and moderation (pubblica così / apri nell'editor / scarta).
- **Acceptance**: unknown block types rejected on write and ignored on render; XSS payloads in content escaped; upload over limit rejected before upload; publishing revalidates `/notizie`; Playwright: create and publish a post with image.
- **Repos**: api, web.

## 7. Super admin, GDPR, accessibility, full e2e
- **Scope**: users & roles (invite staff, change role, deactivate, last-admin protection UX; revisit MFA/TOTP for super admin), org settings (issuer data, VAT exemption text, stamp duty, fee, counters upward only), audit log viewer with filters, GDPR export/anonymise, accessibility pass on `/gestione`, complete Playwright suite (public proposal, staff phone booking, staff login, shift create/assign, volunteer availability, invoice issuance).
- **Acceptance**: all e2e green in CI; anonymisation leaves invoices intact and redacts audit; last super admin cannot be removed (UI + API + DB); settings changes audited.
- **Repos**: api, web.

## 7b. Transports only (rework per ADR-070)
- **Scope**: migration `transports_only` (drop `bookings` + its enums/functions/triggers; transports `contact_phone`, `companions`, `mobility_aids`, `odometer_start/end`, generated `km`, `invoice_id`, drop `booking_id/companion/requested_by/reason/km`; `invoice_lines.transport_id`; `services` drop `price_cents/requires_transport`; `org_settings.km_rate_cents`; new `complete_transport`, `issue_invoice`, `void_invoice`, `staff_org_info`, `volunteer_transports_v`, `gdpr_export`, `anonymize_member`; seed transports instead of bookings, `km_rate_cents = 35`); API: remove bookings module/permissions/error, contract in `data-model.md` §API contract, major bump; web: remove `/gestione/prenotazioni` and booking components, one transport form with member prefill, odometer inputs for volunteer and staff close, invoice from a `svolto` transport with prefilled editable amount, `kmRateCents` in Impostazioni, services without prices.
- **Acceptance**: DB: `bookings` absent; time check, odometer pair/order/svolto checks; `km` = end − start; issue twice → `TRANSPORT_NOT_INVOICEABLE`, void → invoiceable again; volunteer view exposes odometers and `contact_phone` but not `notes`; anonymise nulls `contact_phone`; API: complete with end < start → 400, invoice amount stored as sent, `/bookings` 404, member detail without `bookings`; Playwright: staff creates transport (prefill), volunteer closes it with odometers, staff issues the invoice.
- **Split (parallel)**: db-engineer `api/supabase/migrations/<ts>_transports_only.sql`, `api/supabase/seed.sql`, `api/test/db/**` except `permissions.parity.test.ts`; api-engineer `api/src/**` (incl. `*.test.ts`), `api/openapi.json`, `api/test/staff/**`, `api/test/public/**`, `api/test/db/permissions.parity.test.ts`; web-engineer all of `web/` (hand-edits `lib/api/schema.d.ts` from the contract, regenerated by `make gen-api` at merge).
- **Repos**: api, web.

## 7c. Shared week calendar and grouped actions (after 7b, ADR-071)
- **Scope**: extract the Turni calendar into `components/gestione/week-calendar.tsx` and use it unchanged-looking on `/gestione/turni`, `/gestione/trasporti?week=` (replaces the list), staff `/gestione/disponibilita?week=` and volunteer `/gestione` ("I miei impegni"); grouped actions (primary + "Altro") on transports list/detail and turni header. API: `AvailabilityOverview.items[].canDrive` (contract in `data-model.md` §API contract ADR-071).
- **Acceptance**: vitest `lib/availability-days.test.ts` (rules → volunteers per ISO weekday, `assente` days excluded); API test for `canDrive`; existing `turni.spec` green without edits to its selectors; Playwright: transport created in a far-future week shows in `/gestione/trasporti?week=…`, its card opens the detail; volunteer sees an assigned transport in the "I miei impegni" calendar and can still confirm/close; staff availability calendar lists a volunteer on a rule weekday; axe (no serious/critical) on the four pages; transport detail shows one primary button + "Altro".
- **Split (parallel)**: api-engineer `api/src/modules/volunteers/**`, `api/openapi.json`, `api/package.json` (minor), `api/test/staff/**`; web-engineer all of `web/` (hand-edits `lib/api/schema.d.ts`, regenerated by `make gen-api` at merge). No db-engineer work.
- **Repos**: api, web.

## 8. Deploy guide
- **Scope**: `docs/deploy.md`: link both existing Supabase projects (check contents with `supabase migration list` / `db diff` first, stop if foreign data; verify EU region), Auth settings (hook, redirect URLs, signups off, Resend SMTP, JWT expiry 15 min) on both, storage buckets, Vercel projects api/web (fra1, env per environment, cron, Git settings, deployment protection), domain, `make deploy-check`, first super admin. Remote Auth/API config of both projects must match `api/supabase/config.toml`: access token hook, `enable_signup=false`, `secure_password_change`, min password 12, JWT expiry 900 s, email templates (incl. magic_link, recovery, invite, password_changed notification), redirect URLs, exposed schemas only the empty `api` schema + GraphQL off (ADR-035). Apply with `supabase config push` where supported, otherwise a dashboard checklist verified by `make deploy-check`; email rate limit set in the dashboard.
- **Acceptance**: `make deploy-check` passes against staging; a reviewer follows the guide on staging end to end without extra knowledge. Production migration only with explicit approval.
- **Repos**: workspace (docs, Makefile), api (deploy workflow if adjusted).
